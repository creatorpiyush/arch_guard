# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`arch_guard` (published on pub.dev; the folder is still named `dep_graph_visualizer`, the old package name) is a Dart CLI and library that scans a Dart/Flutter project's import/export directives, finds circular dependencies (Tarjan SCC), enforces layer / forbidden-package / workspace / metric rules from `arch_guard.yaml`, and exports reports (text, HTML, Mermaid, DOT, JSON, SARIF, Markdown).

The repo holds two packages:
- root: `arch_guard` (SDK `^3.8.0`, pure Dart, no `analyzer` dependency).
- `arch_guard_lint/`: an analyzer plugin (SDK `^3.10.0`) that surfaces the same rules in the IDE with quick fixes. It depends on `arch_guard` through `pubspec_overrides.yaml` (`path: ..`). The root `analysis_options.yaml` and `.pubignore` exclude it, so run its checks from inside that folder.

## Commands

```bash
dart pub get
dart format --output=none --set-exit-if-changed .
dart analyze --fatal-infos            # public_member_api_docs is on: public API needs /// docs
dart test
dart test test/layer_validator_test.dart            # one file
dart test test/baseline_test.dart -N 'shrunk'       # tests whose name matches
./tool/pre_commit.sh                  # regenerate vis-network asset, format, analyze, test
./tool/pre_release.sh                 # above + CHANGELOG/version check + pub publish --dry-run

# Try the CLI (sample_project has two cycles and a layer violation on purpose)
dart run bin/arch_guard.dart example/cases/sample_project --no-fail-on-cycle

# Plugin
cd arch_guard_lint && dart pub get && dart analyze --fatal-infos && dart test
```

CLI exit codes: `0` clean, `1` problems, `2` scan error, `64` bad flags.

## Architecture

Pipeline (see `ARCHITECTURE.md` for detail): `bin/arch_guard.dart` → `lib/src/cli/run.dart` (`runCli`) → `ArchAnalysis.run` (`lib/src/analysis/arch_analysis.dart`) → exporters/reporters.

- `ArchAnalysis` is the single source of truth for a run: config load, scan, graph + cycles, layer/package/workspace/metric validators, baseline comparison, and `--since` git filtering. Both the CLI exit code and `expectArchitecture()` in `lib/testing.dart` derive from it, so a test passes exactly when the CLI exits `0`. New rules belong here, not in `run.dart`.
- Scanning (`lib/src/scanner/`) uses regex directive extraction, not the analyzer AST. It handles conditional imports, `package:` URIs, and Dart workspace / Melos members (`pubspec_reader.dart`). `ProjectScanner.scanSources()` scans in-memory content; the lint plugin uses it for unsaved editor buffers.
- Config (`lib/src/models/config_model.dart`) is read from `arch_guard.yaml` or `pubspec.yaml` → `arch_guard:`. Legacy `dep_graph.yaml` / `dep_graph_visualizer:` still load with a deprecation warning. Malformed config becomes warnings, not failures. `preset:` expands via `layer_presets.dart`; `arch_guard init` uses `layout_detector.dart` to pick one.
- Baseline (`lib/src/baseline/baseline.dart`): a cycle is "known" if its files are a subset of a baseline cycle. Layer violations are keyed `source -> target`. Exit codes count only new problems.
- `lib/arch_guard.dart` is the public library export surface, and the lint plugin imports it. Changing exported API affects `arch_guard_lint`.
- `lib/src/assets/vis_network_asset.dart` is generated by `tool/bundle_vis_network.dart`; do not hand-edit it.
- `lib/src/version.dart` must match `pubspec.yaml` (a test enforces this).

## Tests

- `test/fixtures/` holds unit-test projects. `example/cases/*` are user-facing examples whose README claims are pinned by `test/examples_test.dart`. Changing behaviour often means updating an example's expected output there.
- Both fixture trees are excluded from analysis.
- Lint plugin fix tests use `arch_guard_lint/test/fix_support.dart`, because `dart fix` can't exercise single-location fixes.

## Conventions

- Branches: `type/short-description` (e.g. `fix/windows-glob-paths`).
- Every behaviour change needs a user-facing line at the top of `CHANGELOG.md` and doc updates in `docs/` (GitHub Pages site) and the README where relevant. Changelog entries name the new library API at the end (`Library: ...`).
- If HTML report or terminal output changes, regenerate screenshots: `dart run tool/screenshots.dart` (needs Chrome).
- CI (`.github/workflows/verify.yml`) tests on Dart 3.8.0 and stable across Linux/macOS/Windows, so paths must work with Windows separators. It also self-tests `action.yml` against `example/cases/sample_project`.
- `skills/arch-guard/SKILL.md` is the agent skill shipped to users; keep it in sync with CLI behaviour.

## Releases

- Bump `pubspec.yaml` and `lib/src/version.dart`, run `./tool/pre_release.sh`, then push tag `vX.Y.Z`. The tag publishes to pub.dev and builds binaries.
- The plugin is published by tag `arch_guard_lint-vX.Y.Z` via `tool/publish_arch_guard_lint.sh`. That script exports the folder and drops `pubspec_overrides.yaml` before publishing. Its workflow checks the tag against `arch_guard_lint/pubspec.yaml`, so tag only after merge. If the plugin needs a new `arch_guard`, publish `arch_guard` first.
